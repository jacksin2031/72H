# P2.4 — 官方海嘯浸水想定及分類避難場所

日期：2026-10-11 JST。狀態：PARTIAL；石卷試點接入及本地驗收完成，全國風險覆蓋尚未完成。
實作及驗收證據見 `docs/VNEXT_P2_4_VALIDATION.md`。
依使用者方向，這是 P2.3 地圖可讀性之後的主要開發階段。
本文件沒有授予新的移動權限，亦不代表 Preview／Production 已接入下列資料。

## 目標與交付界線

讓使用者看見有來源、版本和覆蓋範圍的海嘯風險資料，以及官方指定場所的災害分類。
第一輪交付是風險查詢及指定場所參考；不輸出「此地安全」、不自動啟用避難導航。
全日本地圖可瀏覽，不等於全日本已完成風險資料驗收。

必須分開三類資訊：

| 資訊 | 用途 | 不能據此推論 |
| --- | --- | --- |
| 津波浸水想定 | 指定情境下的浸水範圍、深度分級 | 本次事件的實際浸水深度或絕對安全 |
| JMA 海嘯警報／注意報／預報 | 予報區的事件資訊、發表／更新／解除 | 個別街道的浸水深度、場所已開放 |
| 指定緊急避難場所／指定避難所 | 官方指定及適用災害 | 現在可進入、容量足夠、沿途可通行 |

## 已核查來源（2026-10-11）

1. [國交省 A40 津波浸水想定](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A40-v2_1.html)：提供都道府縣的浸水面及深度分級，原典是地方政府資料。年度、原典、座標系及地方使用條件須逐份核對，不能把入口頁所列版本當成所有地區的最新版本。官方亦說明實際海嘯可能超出想定。
2. [重ねるハザードマップ開放資料](https://disaportal.gsi.go.jp/hazardmap/copyright/opendata.html)：提供津波浸水想定 PNG tiles，可作官方參考圖層。透明像素、缺少 tile 或 HTTP 錯誤不能當成「零浸水」；圖層顏色不直接成為 Safety Core 證據。
3. [GSI 指定緊急避難場所／指定避難所](https://www.gsi.go.jp/bousaichiri/hinanbasho.html)：兩者用途不同；緊急避難場所按災害分類。公開資料限於市町村登記且同意公開的項目。
4. [GSI CSV 欄位及更新資訊](https://hinanmap.gsi.go.jp/hinanjocp/hinanbasho/koukaidate.html)：包含共通 ID、經緯度及八類災害適用欄位；指定欄位「1」表示適用，空白表示非該類指定。資料庫更新日期不等於指定日期，且可能有未公開場所。
5. [JMA 津波資訊說明](https://www.jma.go.jp/jma/kishou/know/jishin/joho/tsunamiinfo.html)：資訊按津波予報區發表；接入前另核查官方機器資料規格、發布渠道及更正／解除語義。

以上確認的是文件及資料格式，尚未下載、正規化或驗收全國實際資料。

## 現有介面與必要改動

- 重用 `DestinationRecord`、`DestinationProjection`、官方來源註冊、freshness／conflict 及 `spatial.py` 的 movement gates。
- `live_sources.py` 的 GSI CSV adapter 已區分指定用途及八類災害分類；開放狀態仍為 `UNKNOWN`。目錄不能補作當前可用性或安全證據。
- `DisasterEventType` 已加入 `TSUNAMI` 並同步 Python／TypeScript contracts、payload 驗證、來源授權、planner／Safety Core、儲存及舊地震快照相容測試。海嘯 assessment level 為 null，不套用地震 `L0..L4`。
- 八類指定資料使用獨立分類模型，保留指定、非該類指定、缺欄及非法值的差異。場所用途、官方指定適用性及當前可用性維持分開。
- 精確 GPS 留在裝置。下載區域資料後本地查詢；伺服器仍只接收既有 bounded area identity。不得順帶新增精確座標上傳。

## 有限工作包與次序

| 工作包 | 交付 | 驗收條件 |
| --- | --- | --- |
| A：來源及覆蓋清單 | 每區原典 URL、資料／發布／取得日期、版本、SHA-256、CRS、使用條件、覆蓋及限制 | 初始試點實際資料可重現；未提供／未驗收區域明確標示 |
| B：分類場所 adapter | 共通 ID、地方行政區、用途、原始分類、災害適用性及來源 | GSI 指定「1」／空白／缺欄／非法值分開；一般避難所不誤標為海嘯緊急避難場所；open 保持 UNKNOWN |
| C：浸水資料及本地查詢 | 驗證過的分區 polygon／深度級別、GPS 精度範圍查詢、可選參考圖層 | 洞、多重面、邊界、精度跨界、覆蓋缺口、衝突及版本更新測試通過 |
| D：事件與失效處理 | TSUNAMI contract、JMA area-scoped adapter、來源狀態及更新／解除 | 無資料、過期、衝突、offline、reconnecting 保持保守；解除不自動產生安全結論 |
| E：整合驗收 | 手機／桌面 UI、離線資料包、Replay 與 Live 分離、來源說明 | 下列負面驗收全部通過；必要 tests／typecheck／build／secret scan 完成 |

建議先以宮城縣一個資料完整的沿海市町村作試點，方便對照既有 311 歷史案例；實際範圍由 A 的資料核查決定。全國場所目錄可分區匯入，但風險查詢只對逐區通過驗收的覆蓋範圍開放。B、C 可在 A 完成後分開實作，D 依 contract 改動次序進行；E 必須整合驗證。

## 查詢結果與 UI

- 浸水結果分為「位於已知想定範圍」、「未與已核查想定範圍相交」、「邊界／精度不確定」、「資料未覆蓋／不可用」。這些是情境查詢狀態，不是個人安全狀態。
- GPS 誤差範圍與多個深度級別相交時，呈現涉及級別及不確定性，不顯示虛構單點精確水深。
- 地方圖層之外的點仍須有獨立覆蓋清單，才可顯示「未與已核查範圍相交」。只有浸水 polygons 本身，不能證明其外所有地區皆已調查。
- 官方指定建築即使落在浸水區也可能附帶垂直避難／樓層條件；不得單憑點的位置批准或否定。保留原典備註並要求所需條件證據。
- 場所卡顯示用途、適用災害、指定資料日期與來源；另列「目前開放：未核實」、「路線：未核實」。最近距離不是安全排名。
- 深色底圖保留。風險圖層只用必要的官方分級圖例；灰色資料未知區不呈現為綠色安全區。320px 下來源、狀態及警示可讀且不重疊。

## 安全條件及負面驗收

第一輪所有查詢仍保持 `safe_location_verified=false`、`route_authorized=false`。
日後啟用高風險移動，必須通過既有 deterministic Safety Core：來源具該項聲明權限、適用地區及災害、有效且無衝突的移動指示、符合條件且當前開放的目的地、已核實可通行路線、有效 plan/action 與位置及重連驗證。靜態指定資料或想定資料不單獨滿足這些條件。

必要測試案例：

- 有場所、無海嘯分類：不可成為海嘯合資格目的地。
- 適用海嘯、open UNKNOWN／CLOSED：不可成為目前可用目的地。
- 未相交、缺覆蓋清單／過期版本／GPS 不準：不得宣稱安全。
- 透明 tile／404／解析失敗：顯示資料未知，不是無浸水。
- 指定場所的垂直避難條件缺失：不得由 polygon 相交結果作安全批准。
- JMA 警報更新、解除、訂正或跨區衝突：正確失效及重算，不復用失效計劃。
- 離線 reload 保留資料版本及取得時間；重新取得不得重設原本的發布時間或 freshness。
- 歷史演練不冒充 Live；Gemini 說明不得提升查詢、場所或路線的安全權限。
- 舊 EARTHQUAKE 快照、plan history、無精確 GPS 上傳及既有 movement gates 無 regression。
