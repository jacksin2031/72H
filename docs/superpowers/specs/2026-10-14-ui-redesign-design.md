# 72H 介面重整設計規格

狀態：DRAFT，等使用者審閱（2026-10-14 JST）
分支：`codex/ui-redesign`（從 main `9095f85` 開出）

## 1. 目標與使用者決定

讓 72H 的介面**簡單整潔、符合現代審美**，移除或簡化不必要的部分，**盡量不使用卡片、框框**。

| # | 使用者決定 |
|---|---|
| U1 | 主要對象：**在日本遇到災害的真實使用者**。慌亂中、可能在戶外、單手操作也要能用 |
| U2 | **演練畫面（demo／模擬／災害測試）和真實畫面完全一樣**，只用「演練」標籤區分 |
| U3 | **深色為主**，保留高對比模式供陽光下使用 |
| U4 | 主結構改為三個分頁：**現在／地圖／更多** |
| U5 | 做法 A：先建立統一的設計規則與共用元件，再分階段重做每個畫面 |
| U6 | 檢查並移除不必要的文字與內容（技術用語、重複說明、過長文字） |

**不變的部分**：安全邏輯、API、資料契約、測試覆蓋的行為都不改。這次只改「呈現方式」。AGENTS.md 的安全規則全部保留：依據與時間、「演練」與「AI 建議」標籤，以及不暗示安全。

## 2. 設計規則（Design tokens）

所有數值集中定義在一個新檔案 `apps/web/app/tokens.css`，元件只能使用這些變數。

### 2.1 顏色

| 用途 | 深色（預設） | 高對比（淺色） |
|---|---|---|
| 背景 `--bg` | `#0B0D10` | `#FFFFFF` |
| 主要文字 `--text` | `#F2F4F6` | `#0B0D10` |
| 次要文字 `--text-2` | `#9AA3AD` | `#3D4651` |
| 分隔線 `--line` | `rgba(255,255,255,.08)` | `rgba(0,0,0,.14)` |
| 危險 `--danger`（官方警報、立刻行動、求救） | `#FF5A52` | `#C4120A` |
| 注意 `--warn`（注意、資料過期） | `#FFB020` | `#8A5A00` |
| 正常 `--ok`（已確認） | `#3DDC97` | `#0B7A4B` |
| 資訊 `--info`（連結、「AI 建議」） | `#6CB6FF` | `#0A58B0` |
| 演練 `--exercise` | `#B49CFF` | `#5B3DC4` |

- 平常的畫面幾乎只有黑白灰；**顏色只用來表示狀態**。
- 所有文字和背景的對比都要達到 WCAG AA（一般文字 ≥ 4.5:1）。

### 2.2 字體與字級
- 字型使用系統字體：`system-ui, "Hiragino Sans", "Noto Sans JP", "PingFang TC", "Noto Sans TC", sans-serif`。不下載網路字型，所以離線也能正常顯示。
- 字級只有四級：
  - `--fs-hero`：28px（寬螢幕 32px），粗體 700，只用於主要指示
  - `--fs-title`：20px，600
  - `--fs-body`：16px，400，行高 1.5（全站最小字級）
  - `--fs-meta`：14px，400，用於次要說明、時間、依據

### 2.3 間距與版面
- 間距級距：4／8／12／16／24／32／48px。
- 畫面左右邊距 20px；內容最大寬度 640px，置中。**桌面版和手機版共用同一個單欄版面**，只是更寬。
- 區塊之間的間距是 24–32px。

### 2.4 「不用框框」的分區規則
- **用留白分區**；每一區上方放一個 `--fs-meta` 的灰色小標題。
- **列表**：每一列是「文字＋次要值＋右箭頭」，列與列之間只用一條 `--line` 細線，**不包成卡片**。
- **禁止**：卡片外框、陰影、背景色塊分區。
- **圓角只用在**：按鈕（12px）、地圖、底部抽屜的上緣、小標籤（膠囊形）。

### 2.5 狀態色帶
- 有警報、過期或演練時，畫面最上方出現一條**橫跨全寬的色帶**（高 44px），內容像「大津波警報 · 剩 05:00」或「演練」。
- 色帶的顏色依狀態：危險紅、注意琥珀、演練紫。平常沒有狀態時不顯示。

### 2.6 按鈕
- **主要按鈕**：填色、全寬、高 52px。**每個畫面最多一個**。
- **次要按鈕**：只有文字，沒有底色。
- **危險按鈕**：紅色填色，只用在求救相關動作。
- 所有可點擊的元素至少 48×48px。

### 2.7 其他
- 圖示統一使用 `ui-icon` 的線條圖示，24px。
- 動畫最多 150ms；如果系統設定了 `prefers-reduced-motion: reduce`，就關閉所有動畫。
- 主題設定沿用現有的「深色／跟隨系統／高對比」選項。

## 3. 共用元件

新增 `apps/web/components/ui/` 目錄，每個元件只負責一件事：

| 元件 | 用途 |
|---|---|
| `AppShell` | 頂部狀態色帶＋內容區＋底部三分頁導覽（現在／地圖／更多）；演練模式時另加底部操作列 |
| `StatusBand` | 狀態色帶（level、文字、倒數） |
| `Section` | 留白分區＋小標題 |
| `ListRow` | 列表列（主文字、次要值、箭頭或開關），列與列之間用細線 |
| `Button` | primary／secondary／danger |
| `Tag` | 膠囊小標籤：「演練」「AI 建議」 |
| `Disclosure` | 點一下展開的區塊（用於「依據」「了解更多」） |
| `BottomSheet` | 地圖頁的底部抽屜 |

演練畫面不另外做元件，直接重用以上元件（U2）。

## 4. 畫面

### 4.1 「現在」頁（取代原本的首頁、計畫歷史、資訊來源分頁）
由上往下：
1. `StatusBand`：只在有警報、過期或演練時出現。
2. **一句主要指示**（`--fs-hero`）。沒有警報時顯示「目前沒有警報」。
3. **依據**：一行 `--fs-meta`，例如「氣象廳 大津波警報 · 14:51 發布」。點一下展開 `Disclosure`，裡面有計畫歷史、資訊來源和 AI 解釋。
4. **主要按鈕「我需要幫助」**（危險紅）：按下才展開狀況按鈕、錄音、求救。平常不佔畫面空間。
5. **接下來／避免**：兩個 `Section`，各有一到兩行文字。
6. **更新時間**：一行 `--fs-meta`；離線時顯示「離線 · 最後確認 HH:MM」。

### 4.2 「我需要幫助」展開後
- 主要指示永遠放在**最上方**。這也修正真機發現的 D1：AI 建議求救時，SOS 不可以排到主要指示上面。
- 只有使用者自己回報 TRAPPED／INJURED／MOBILITY_LIMITED 時，求救區才直接放在主要指示的正下方。
- 七個狀況按鈕是膠囊形的切換按鈕；下面是錄音（主要）和打字（次要）。
- AI 影響的項目用 `Tag`「AI 建議」標示。

### 4.3 「地圖」頁
- 地圖佔滿整個畫面。左上角是地區選擇；右側是圓形的縮放和「我的位置」按鈕。
- 圖層開關是一排膠囊：浸水想定、避難場所、海嘯預報區、道路候選。圖例只在對應圖層打開時，用一行小字顯示。
- `BottomSheet` 平常只露出一行（「附近 N 處指定避難場所」），往上拉才顯示列表（名稱 · 適用災害 · 距離）。道路候選區只在有候選路線時出現。
- 原本頁面上的 4–5 個面板（全國避難所、官方海嘯、即時參考、路線評估、指定場所）**合併成這一個抽屜**，用小標題分區。
- 歷史震央選擇移到「更多 → 演練與示範」。

### 4.4 「更多」頁
一個 `ListRow` 列表：語言、外觀、電量模式、緊急聯絡人、位置與隱私、通知、資訊來源、演練與示範、關於。

### 4.5 演練畫面
- 直接使用「現在」和「地圖」。
- 頂部是紫色 `StatusBand`「演練」；底部多一條操作列：「下一則更新 → ｜ 暫停 ｜ 重新開始」。
- Agent 紀錄、Judge 資訊只放在「依據 → 詳細」裡面。

### 4.6 路由
- `/`、`/dashboard` → 「現在」
- `/plan`、`/sources` → 「現在」，並自動展開「依據」（保留舊連結）
- `/map` → 「地圖」
- `/more` → 「更多」；`/notifications` → 「更多 → 通知」子頁
- `/demo`、`/trace`、`/simulation`、`/disaster-test` → 演練模式的「現在」或「地圖」

## 5. 文字盤點原則

| 類型 | 處理方式 |
|---|---|
| 給一般人看的技術用語（Service Worker、JavaScript/CSS、session、Judge Mode、Agent 紀錄） | 從一般畫面移除，只放在「更多 → 演練與示範／開發者」 |
| 重複的免責聲明（安全性未判定、不可作避難導航、不代表沒有危險、最安全路線未判定） | **每頁只保留一次**，用 `--fs-meta` 放在「依據」下方 |
| 過長的說明（例如 111 字的位置隱私說明） | 縮成一句話，加上「了解更多」`Disclosure` |
| 清單式狀態（路線評估 7 行「未核實」） | 收成一行「還有 N 項未確認」，可以展開 |
| 重複的入口 | 每個功能只保留一個入口 |
| 演練專用文字出現在真實畫面 | 只在演練模式顯示，統一換成 `Tag`「演練」 |

**一定保留**：官方依據與資料時間、「演練」標籤、「AI 建議」標籤、一次「不代表安全」的說明。

每個階段實作時，都把該階段的畫面截圖、列出「刪除／縮短／移位」的文字清單，並寫進該階段的驗收紀錄。

## 6. 階段

| 階段 | 內容 | 完成條件 |

| 1 | `tokens.css`、`components/ui/*`、`AppShell`（三分頁＋單一版面），以及路由對應 | 所有既有頁面能在新外殼下正常運作；既有測試通過 |

## 7. 測試與驗收
- 既有的行為測試全部要繼續通過，安全相關的斷言不可以刪除。
- 新增共用元件的單元測試：渲染、鍵盤操作、`aria` 屬性。
- 新增「無卡片」的守衛測試：掃描 CSS，禁止 `box-shadow`，以及共用元件以外的 `border`／`border-radius`（地圖相關樣式除外）。
- 新增對比度測試：檢查 tokens 的顏色組合是否達到 4.5:1。
- 每個階段完成後，在 ROG Phone 6 上用 adb 截圖驗收，並檢查 320px 和 360px 寬度。

## 8. 不在範圍內
- 不改安全邏輯、後端與資料契約。
- 不新增 UI 框架或套件。
- 不部署。
